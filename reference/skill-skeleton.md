> repackager that turns the 9 latest-AIOS core zips in `module-installs/latest-aios/core/`

> Pasted only if a phase stalls past its time box.

## Findings from probing the zips (load-bearing assumptions)

1. **All 9 expected zips exist** in `module-installs/latest-aios/core/`. Filenames are stable: `context-os-v1.zip`, `data-os-v1.zip`, `infra-os-v1.zip`, `intel-os-v1.zip`, `command-os-v1.zip`, `productivity-os-v1.zip`, `daily-brief-v1.zip`, `slash-commands-v1.zip`, `aios-starter-kit.zip`.
2. **Each zip ships its own `INSTALL.md`.** The bundle never tries to interpret or merge those - it copies the zip verbatim, and Claude Code on the target follows each INSTALL.md in turn.
3. **Sha256 per zip is recorded in the manifest** so the receiving end can verify integrity before unpacking anything.
4. **Pure-input model.** The skill reads only from `--source`. The surrounding workspace is never opened. This is intentional and load-bearing - it's the reason a member can build a bundle inside their personal AIOS without risk of leaking client work.

## Phase 2 output - `scripts/pack.py`

Single script. No demo workspace, no fragment walking, no drift, no skeleton. Stdlib + pyyaml.

Logic:

1. Resolve `--source` (default `module-installs/latest-aios/core`). Verify all 9 expected zips exist; abort listing missing files.
2. Compute sha256 of each zip.
3. Render `templates/manifest.template.yaml` -> `manifest.yaml` with `version`, `generated_at`, `source_dir`, `install_order`, `gates`, per-zip `{path, sha256, bytes}`.
4. Stage a temp dir: 9 zips (bare filenames) + `manifest.yaml` + `install.sh` (from templates) + `INSTALL-PROMPT.md` (from templates).
5. Tar staging -> `<out>/<version>/aios-bundle-<version>.tar.gz`.
6. Write `<out>/<version>/BUNDLE.json`: version, sha256_of_tarball, file_count (12), generated_at, source_dir, zip_count (9), tarball name.
7. Drop a copy of `manifest.yaml` next to the tarball.

Full code lives at `.claude/skills/aios-bundler/scripts/pack.py`.

Key snippet - render_manifest:

```python
def render_manifest(version: str, source_dir: Path, zip_meta: list[dict]) -> str:
    template = (TEMPLATES / "manifest.template.yaml").read_text()
    zips_block = yaml.safe_dump(zip_meta, sort_keys=False, default_flow_style=False).rstrip()
    indented = "\n".join(("  " + line) if line else line for line in zips_block.splitlines())
    return (template
        .replace("{{VERSION}}", version)
        .replace("{{GENERATED_AT}}", datetime.now(timezone.utc).isoformat())
        .replace("{{SOURCE_DIR}}", str(source_dir))
        .replace("{{ZIPS_BLOCK}}", indented))
```

## Phase 3 output - `templates/install.sh`

Stage-1 bootstrap. Lives inside the bundle at the tarball root.

```bash
#!/usr/bin/env bash
# install.sh - Stage 1 of the AIOS bundle install.
set -euo pipefail

TARGET="${1:-$HOME/aios-new}"
FORCE="${2:-}"
HERE="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"

if [[ ! -f "$HERE/manifest.yaml" ]]; then
  echo "ERROR: manifest.yaml not found next to install.sh ($HERE)." >&2
  echo "       Did you extract the tarball first?" >&2
  exit 1
fi

if [[ -e "$TARGET" && -n "$(ls -A "$TARGET" 2>/dev/null || true)" && "$FORCE" != "--force" ]]; then
  echo "ERROR: $TARGET exists and is not empty. Pass --force to override." >&2
  exit 1
fi

mkdir -p "$TARGET"

cp "$HERE"/*.zip "$TARGET/"
cp "$HERE/manifest.yaml" "$TARGET/"
cp "$HERE/INSTALL-PROMPT.md" "$TARGET/"

# Print stage-2 instructions: cd $TARGET, claude ., paste INSTALL-PROMPT.md
```

No venv setup, no requirements install, no `.env` seed - that's owned by individual layer INSTALL.mds (e.g. infra-os-v1).

Full file at `.claude/skills/aios-bundler/templates/install.sh`.

## Phase 3 output - `templates/INSTALL-PROMPT.md`

Plain markdown the operator pastes into `claude .` on the target.

Structure:

1. **Pre-flight.** Read `manifest.yaml`. Verify all 9 zips present + sha256 matches. Print summary (version, layers, gates). Wait for "go".
2. **Per-layer flow.** For each zip in `install_order`:
   - Extract to a tempdir (sandboxed - never extract into the target directly).
   - Find `INSTALL.md`, print first ~40 lines.
   - Gate handling: if layer is in `manifest.gates`, print the reason and wait for "confirm". Otherwise simple "press enter".
   - Special handling at `aios-starter-kit.zip` (first): no top-level INSTALL.md - copy the skeleton contents into the target directly.
   - Special handling at `infra-os-v1.zip`: confirm GitHub username, repo name, usable token. Do NOT call `gh repo create` - infra's INSTALL.md owns that.
   - Follow the steps in that layer's INSTALL.md exactly. Stop on failure.
3. **Post-install.**
   - **Archive the source zips.** After all 9 layers have installed, move the 9 zips + `manifest.yaml` from the target root into `module-installs/latest-aios/core/` (create the dir first). This matches the canonical AIOS layout so the resulting workspace can re-bundle itself later. Leave `INSTALL-PROMPT.md` at the root for reference. Confirm with `ls module-installs/latest-aios/core/` (expect 9 zips + manifest.yaml).
   - Run `/prime` if available. Print version + sha256.

Hard rules: never read/write outside target + tempdirs; never push to a remote unless an INSTALL.md says so; never skip a gate.

Full file at `.claude/skills/aios-bundler/templates/INSTALL-PROMPT.md`.

## Phase 4 output - `reference/install-order.md`

Documents one paragraph per layer explaining *why* the locked order. Key beats:

- **starter-kit first** - ships the empty workspace skeleton (`.claude/commands/`, `.claude/skills/`, `context/` stubs, `.env` template, empty `module-installs/` and `plans/`) plus the bootstrap commands `/prime`, `/install`, `/create-plan`, `/implement`, `/share`, `/task-audit`. It is the substrate, not an overlay. No top-level INSTALL.md - the installer just copies it into the target.
- **context-os second** - context-os's own INSTALL.md states "this is the very first module they install - it turns a blank template into a workspace". That blank template is the starter-kit.
- **data third** - schemas + migrations precede any layer that wants to log into a DB.
- **infra fourth** - operator needs a remote before any layer wants to commit. **Confirmation gate.**
- **intel** - depends on data + context.
- **command, productivity, daily-brief, slash-commands** - functional layers, order between them is mostly cosmetic.

Plus the "why not starter-kit last" sidebar - the intuitive (and wrong) order is "kit last as a finishing overlay". That assumes the kit is templates *over* the operating layers. It is not - it is the substrate *under* them. The 8 OS layers' install flows expect `.claude/commands/`, `context/`, `module-installs/`, and `.env` to already exist.

Full file at `.claude/skills/aios-bundler/reference/install-order.md`.

## Known gotchas (rehearsal-verified)

- **The skill must be pure-input.** Any read of the surrounding workspace breaks the value proposition (members run this inside a personal AIOS to ship a bundle to a client - leakage is the failure mode).
- **`pack.py` resolves `--source` to an absolute path** before recording it in `manifest.yaml`. The receiving end never needs that path - it's recorded for traceability only.
- **Manifest gates live in the manifest, not the code.** Adding a gate at a future layer is a manifest edit. The `INSTALL-PROMPT.md` reads `gates` from the manifest at install time.
- **`install.sh` does not seed a venv or `.env`.** Each layer's INSTALL.md owns its own setup. Centralising in `install.sh` would smear ownership and create cross-layer assumptions that break when layers evolve.
- **Cross-platform tar.** Default `tar -xzf` works on macOS + Linux. Windows is out of scope; document in SKILL.md as future work.
- **Idempotency of `install.sh`.** Refuses non-empty target without `--force`. Re-running with `--force` overwrites; doesn't delete.
- **No drift audit here.** Out of scope. Captured as the future `aios-drift-audit` skill in `## Out of Scope` of `concept.md`.
